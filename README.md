# MdToDocx

Сборка Markdown-файлов из дерева папок в один DOCX с оформлением по шаблону.

## Требования и запуск

Python 3.9+ и [Pandoc](https://pandoc.org/installing.html) в `PATH`.
Дополнительных Python-пакетов не требуется.
Установка Pandoc на macOS: `brew install pandoc`; на Ubuntu/Debian:
`sudo apt install pandoc`.

```sh
python3 md_to_docx.py ./materials --template ./template.docx --output ./result.docx
```

Короткие аргументы: `-t`, `-o`. Пути с пробелами заключайте в кавычки.
Шаблон необязателен: без `--template` используется стандартное оформление Pandoc:

```sh
python3 md_to_docx.py ./materials --output ./result.docx
```

Папки результата создаются автоматически. Для замены результата добавьте
`--force`. При ошибке преобразования существующий результат сохраняется.
Коды возврата: `0` — успех, `1` — ошибка конвертации, `2` — неверные аргументы.

## Порядок обхода

Сначала все `.md`-файлы текущей папки по алфавиту, затем рекурсивно подпапки
по алфавиту. Например:

```text
materials/
├── 02-intro.md                 # 1
├── 10-summary.md               # 2
├── a-chapter/
│   ├── 01-start.md             # 3
│   └── nested/
│       └── details.md          # 4
└── b-chapter/
    └── appendix.md            # 5
```

Сортировка лексикографическая, без учёта регистра, с Unicode-нормализацией NFC;
при совпадении учитывается исходный регистр. Она не зависит от системной локали.
Для числовой очередности используйте префиксы одинаковой длины: `01`, `02`, `10`.
Расширение `.MD` поддерживается. Другие файлы игнорируются.
Скрытые папки и файлы включаются, символические ссылки пропускаются.
Отсутствие Markdown-файлов во всём дереве считается ошибкой.

## Шаблон

Создайте исходный шаблон Pandoc:

```sh
pandoc --print-default-data-file reference.docx > template.docx
```

Откройте его в Word или LibreOffice, настройте стили (`Normal`, `Body Text`,
`Heading 1`, `Heading 2`), поля, размер страницы и колонтитулы, затем сохраните.
Передайте файл через `--template`.

Шаблон используется как `reference-doc` Pandoc: его основной текст не копируется,
заполнение плейсхолдеров вроде `{{content}}` не поддерживается.

## Markdown

Файлы должны быть в UTF-8 (допускается BOM). Используется диалект Pandoc Markdown:
заголовки, списки, таблицы, ссылки, изображения, блоки кода и сноски.
Файлы разбираются отдельно: определения ссылок и сносок действуют внутри файла.
Относительные пути изображений вычисляются от папки соответствующего Markdown-файла;
одинаковые имена изображений в разных папках не конфликтуют.
Для внешних изображений может потребоваться сеть. Предупреждения Pandoc,
в том числе о недоступных изображениях, считаются ошибками.

Имена файлов и папок не добавляются в текст. Заголовки берутся из Markdown.
Автоматических разрывов страниц между файлами нет. YAML-метаданные файлов
не переносятся в общий документ. Произвольный HTML и ссылки между `.md`-файлами
не преобразуются в специальные элементы Word или внутренние переходы.

```sh
python3 -m unittest discover -s tests -v
```

Интеграционные тесты требуют Pandoc и проверяют реальный DOCX.
